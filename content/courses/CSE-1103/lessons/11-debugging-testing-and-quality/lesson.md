# Debugging, Testing, and Program Quality

## Objectives

- Separate syntax, runtime, and logic errors.
- Design test cases using normal, boundary, and invalid inputs.
- Improve readability and maintainability.

## Debugging loop

1. Reproduce the problem.
2. Reduce it to the smallest failing case.
3. Form a hypothesis.
4. Inspect values with prints or a debugger.
5. Change one thing.
6. Re-run the test.
7. Record the cause and fix.

## Test design

For a grade calculator, test normal marks, the lowest valid mark, the highest valid mark, values just outside the range, and non-numeric input.

## Quality checklist

- Meaningful names
- Small functions
- Consistent formatting
- No duplicated logic
- Input validation
- Clear output
- Comments explaining decisions, not obvious syntax

## Assignment

Review one earlier program. Create a bug report, add three tests, fix the issue, and document what changed.
